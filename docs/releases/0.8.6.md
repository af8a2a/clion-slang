# 0.8.6 — Exclude build snapshots from symbol search

The remaining duplicate rows were different physical files, not repeated delivery of the same
declaration: Metallic's build directory contained experiment snapshots of the Shader tree.
0.8.5's declaration-identity deduplication intentionally preserved these files.

Symbol search now excludes `build/` and `cmake-build-*` immediately beneath project/content
roots by default. Both name enumeration and result delivery use the filtered scope, and result
callbacks also explicitly verify membership. Existing indexed snapshots disappear from results
without deleting files, changing project exclusions, or rebuilding the index.

A project setting, **Include symbols from build/ and cmake-build-* directories**, restores these
results when needed. It defaults off for new and existing projects, persists with project settings,
and takes effect on the next search. Normal source files, distinct overloads and the IDE's selected
scope remain respected. The bundled slangd is unchanged.

Validation: 137 available JUnit tests passed, 1 optional test skipped. The actual Metallic corpus
contained 42 relevant source/snapshot files: cullingCamera and materialClassForPixel each appeared
21 times without filtering, and exactly once with the new policy, both in the primary Shaders tree.
Tests cover 30 copied trees, additional content roots, CMake directories, path boundaries, case
rules, original-scope restrictions and settings persistence. Native fixture coverage for enabling
and disabling snapshot search is included but remains unrun because its test-framework dependency
is unavailable. A live installed-popup check is not claimed.
