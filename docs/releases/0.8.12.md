# 0.8.12 — Ctrl-hover on variable declarations

Ctrl-hover now underlines the identifier at local/global variable, field, static field and
parameter declarations. The bundled server returns an exact declaration-name target, and
the plugin retains that self target instead of discarding it. Ctrl-click at a declaration
stays at that declaration; references and builtin calls retain their existing destinations.
No links are invented for unresolved tokens or comments. External servers must return a
definition target for declaration names to gain this behavior.

Includes enhanced runtime patch 0012 and regression coverage for precise name ranges,
word-end carets, generic parameters, existing references and builtin navigation, and unsaved
UTF-16/CRLF edits.

## 中文

按住 Ctrl 悬停在变量声明名称上也会显示下划线，覆盖局部变量、全局变量、字段和参数。
下划线仅覆盖名称；在声明处 Ctrl 点击保持在该声明，变量引用及内置函数仍跳转到原定义。
安装后重启 CLion，并使用自带增强 slangd。

## Validation

- Six focused navigation tests passed on the 261.25134.137 platform, including actual
  `GotoDeclarationAction.getCtrlMouseData` checks for declaration, reference and macro identifier ranges.
- Twelve bundled real-server smoke suites passed, including declaration navigation and existing member colors.
- The previous runtime reproduced the missing declaration target before the fix.
- Local platform verification used the official matching test-framework/common/core artifacts
  through a temporary Gradle init script because the cached framework had incompatible APIs.
  Only the Slang plugin and its dependencies were loaded; tests inject server replies without
  replacing the IDE's concrete LSP manager or starting a real server inside the fixture.
- Interactive Ctrl-hover in the user's running IDE remains unverified.
