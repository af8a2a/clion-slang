# 0.8.18

Fix false undefined-identifier diagnostics when opening an `implementing` file
whose primary module supplies namespace `using` directives. In Metallic's
`StreamRasterCooperative.slang`, this restores resolution of
`resolveVisibilityRecordIndex` and other names provided by the owner's
`using Metallic.GPUDriven` directive.

The bundled Slang language server now places the explicit primary module's
top-level namespace directives in an enclosing scope and wires them before
checking the fragment. Local directives keep their precedence. Using directives
from sibling files or imported modules remain isolated, and genuinely undefined
names still produce diagnostics. Shader source changes are not required.

The real-server regression covers both primary-module and implementing-file entry
points, nested namespace directives, generic constraints, extension targets,
local shadowing, namespace isolation, missing names, unsaved buffers and CRLF text.

Validation: all 16 bundled-server smoke suites pass. The unchanged
`StreamRasterCooperative.slang` has no error diagnostics, and its resolver's hover
and definition navigation reach `GPUDrivenRasterCommon.slang:65`. The owner's
Metallic Slang 2026.18.2 `-no-codegen` check succeeds with existing warnings.

A read-only LSP scan of all 250 current Metallic shaders completes with 204 files
free of error diagnostics. The other 46 retain exactly the same error diagnostics
as the published 0.8.17 runtime under the same search-path configuration
(`Shaders`, `Shaders/Modules`, `Shaders/Interop`, recursive workspace search off).
These include missing external includes, module lookup and language-version
issues; this result does not claim a clean full-project compilation. No Metallic
source files were changed. Interactive CLion UI behavior was not manually tested.
