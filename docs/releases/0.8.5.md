# 0.8.5 — Deduplicate symbol search results

Repeated callbacks and recreated PSI views must not produce multiple rows for the same Slang
declaration. Symbol name enumeration and result delivery now deduplicate within each invocation.
Navigation items use stable project/canonical-file/declaration-offset identity, shared by equals,
hashCode and PSI equivalence. Filesystem case rules and canonical aliases are respected.

Function overloads at different offsets and declarations in different files remain separate.
Deduplication is query-local, so later searches still return the symbol. Processor stop signals
and cancellation remain effective. No index format or bundled slangd change is required.

Validation: 133 available JUnit tests passed, 1 optional test skipped. New regression tests cover
30 repeated callbacks, separate PSI wrappers, presentation changes, native CLion Search Everywhere
equality, overloads, same-named files, canonical aliases, case sensitivity and processor stopping.
The real Metallic shader corpus still extracts exactly one cullingCamera declaration from
GPUDrivenCullingCommon.slang. The plugin archive and bundled runtime hashes were verified.

Tests use installed CLion 2026.2.2 classes, including its actual PsiElementsEqualityProvider.
The full IDE fixture suite remains blocked by the unavailable test-framework dependency;
a live popup check is not claimed. Existing minimum-version/local-SDK build warnings remain.
