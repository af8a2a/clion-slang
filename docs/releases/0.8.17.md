# 0.8.17

Interface-derived-type navigation now follows `typealias` and simple `typedef`
targets, including generic aliases and multi-step alias chains. For example,
Metallic's `ISceneSurfaceMaterialProgram` finds both `OpenPBRMaterialProgramImpl`
and the `OpenPBRMaterialProgram` / `SceneOpenPBRMaterialProgram` aliases.
The gutter tooltip reports derived types and aliases separately; aliases retain
their own icon, signature and navigation location in the popup.

Namespace `using` directives now participate in name resolution within their
lexical scope. Imports in one namespace do not leak into a sibling. Conflicting
imported names remain unlinked. Generic parameters and associated-type
requirements are not inheritance edges, including parameters declared by an
enclosing type or a constrained extension. Pointer/array typedefs are not
treated as transparent aliases of their element type.

Validation used the current read-only `E:/metallic/Shaders` corpus: 250 `.slang`
files, all 22 interfaces and 32 explicit inheritance relationships. The native
index test checks the real OpenPBR alias chains and guards against incorrectly
listing `ContextScatter`, `Material` and material-result wrappers as interface
implementations. The two current `Material<TProgram>` extensions add methods
under generic constraints; neither declares interface conformance.

Re-run the optional corpus test with:

```powershell
./gradlew test --tests '*SlangInheritanceCorpusPlatformTest' -PslangCorpusTestPath=E:/metallic/Shaders
```

The corpus test uses temporary IDE fixture files and leaves Metallic untouched.
Without the property, that optional test is skipped. Focused tests also cover
alias serialization, namespace ambiguity, gutter counts, unopened files,
unsaved edits, cycles, navigation offsets and build-snapshot filtering.

This remains declaration-based navigation, not a compiler conformance proof.
Generic arguments are erased; dependent aliases such as `TModel.Closure`,
extension-declared conformances, module export visibility and active macro
variants are not semantically resolved. Current-corpus coverage does not imply
support for every possible Slang language construct. The UI remains a gutter
marker and native popup; interactive CLion appearance is not manually verified.
